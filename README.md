# LeakLock

LeakLock — системный kill switch для macOS, который работает поверх VPN-клиента. Он
разрешает выход в интернет только через проверенный VPN-туннель, а при обрыве,
переподключении или сбое VPN блокирует трафик на уровне файрвола.

## Совместимость

Проверено с **AmneziaVPN**, включая раздельное туннелирование. **Incy** из App Store
(режим VPN через Network Extension) определяется так же: туннель `utun` с маршрутом
по умолчанию. Другие VPN-клиенты, которые создают туннель `utun`, скорее всего, тоже
подойдут, но пока официально не поддерживаются. Требуется macOS 13 или новее.

Раздельное туннелирование Incy (списки Direct в профиле маршрутизации) работает
внутри клиента, а не через маршруты macOS: для системы весь трафик идёт в туннель,
и Incy сам отправляет «прямые» соединения через Wi-Fi. LeakLock не отличает их от
утечки и по умолчанию блокирует. Чтобы такие профили (например, RoscomVPN) работали,
включите в настройках **«Доверять маршрутизации Incy»**: пока Incy подключён и туннель
проверен, трафик мимо туннеля не блокируется, а при обрыве, выключении VPN или
несовпадении IP всё снова закрыто. С другими VPN-клиентами (например, Amnezia) настройка
не действует: служба проверяет через `scutil --nc list`, что подключён именно Incy.
Включайте её только вместе с kill switch самого Incy: пока он подключён, macOS не
выпускает другие программы мимо туннеля. Если выключить Incy вручную, трафик может уйти
напрямую в течение доли секунды, пока служба не заметит пропажу туннеля.

## Установка

1. Скачайте `LeakLock-x.y.z.dmg` из [Releases](https://github.com/sotnikov-nk/LeakLock/releases)
   и перенесите приложение в «Программы».
2. При первом запуске macOS заблокирует неподписанное приложение. Откройте «Системные
   настройки → Конфиденциальность и безопасность» и нажмите «Всё равно открыть».
3. В меню щита нажмите «Установить службу…» и введите пароль администратора.
4. В «Настройках» укажите IP-адрес VPN-сервера и включите защиту.

## Как это работает

LeakLock состоит из двух частей. **Служба `leaklockd`** запускается через launchd от
root при старте системы и управляет блокировкой. **Приложение в строке меню** показывает
статус и передаёт службе настройки через Unix-сокет. Защита не зависит от того, открыто
ли приложение.

Блокировку выполняет встроенный файрвол macOS **pf**: служба держит собственный якорь
`com.apple/050.LeakLock`, который подключается к стандартному `/etc/pf.conf`. Фильтрация
идёт в ядре, поэтому трафик блокируется в момент обрыва VPN, без участия службы, и
правила остаются в силе, даже если служба упала.

Служба переключает якорь между тремя состояниями:

| Состояние | Условие | Что разрешено |
|---|---|---|
| Заблокировано | туннеля нет | только исключения (см. «Что работает без VPN») |
| Проверка | туннель появился | исключения и HTTP/DNS через туннель для проверки IP |
| Защищено | внешний IP совпал с IP VPN-сервера | весь трафик, но только через туннель |

- **Обнаружение туннеля.** Туннелем считается интерфейс `utunN` с наибольшим числом
  IPv4-маршрутов. Служба отслеживает таблицу маршрутов по событиям `PF_ROUTE`
  и раз в секунду.
- **Проверка IP.** Сам туннель ещё не доказывает, что VPN работает. Служба запрашивает
  внешний IP у `api.ipify.org`, `checkip.amazonaws.com`, `icanhazip.com` или
  `ifconfig.me` через сокет, привязанный к туннелю (`IP_BOUND_IF`), поэтому запрос
  не может уйти через Wi-Fi. Доступ открывается только при совпадении с IP сервера
  и периодически перепроверяется.
- **Соединения.** Состояния pf для туннеля привязаны к интерфейсу
  (`keep state (if-bound)`), поэтому открытое через VPN соединение не перейдёт на Wi-Fi.
  При любом ужесточении правил служба сбрасывает таблицу состояний.
- **Самоконтроль.** С настраиваемым интервалом (по умолчанию 1 с) служба проверяет, что
  pf включён, якорь вызывается основным набором правил, а сами правила и таблица адресов
  не изменены. Найденные расхождения она исправляет, а если исправить не может,
  показывает ошибку.

## Режимы блокировки и раздельное туннелирование

- **Весь интернет.** Без VPN блокируется весь исходящий трафик, кроме исключений.
  Рекомендуется для чужих сетей.
- **Адреса из VPN.** Блокируется только то, что VPN-клиент направляет в туннель.
  Служба запоминает эти маршруты (например, `0/1` и `128.0/1` за вычетом прямых
  маршрутов раздельного туннелирования) и продолжает блокировать их после обрыва VPN.
  IPv6 вне туннеля блокируется всегда. Пока маршруты неизвестны, блокируется всё.

Список маршрутов сам только пополняется. Если вы сузили список VPN в Amnezia, нажмите
в настройках «Забыть выученные маршруты» при подключённом VPN.

Раздельное туннелирование в Amnezia работает в двух противоположных режимах:

1. **«Через VPN только адреса из списка».** Без VPN LeakLock блокирует только их.
   Добавьте в список сервисы проверки IP (см. выше), иначе проверка не пройдёт.
2. **«Через VPN всё, кроме адресов из списка».** Без VPN LeakLock блокирует всё,
   кроме них.

## Что работает без VPN

Всегда разрешены: соединение с VPN-сервером, DHCP, loopback, link-local и mDNS, а также
AWDL (AirDrop, AirPlay, повтор экрана iPhone, Sidecar). Эти пути не выходят в интернет
за пределы локального сегмента.

По желанию в настройках можно разрешить:

- **Локальную сеть:** принтеры, сетевые диски, роутер.
- **DNS:** нужен, только если в VPN-клиенте сервер указан доменом, а не IP. Учтите, что
  DNS-запросы тогда идут мимо VPN.

## Ограничения

LeakLock защищает от сбоев VPN, а не от программ на самом Mac: администратор может
выключить защиту. В первые секунды загрузки системы, до запуска службы, правил ещё нет.
В режиме «Адреса из VPN» список берётся из таблицы маршрутов, которую может изменить
чужая сеть.

## Экстренное отключение и удаление

Снять блокировку без приложения:

```sh
sudo launchctl bootout system/com.leaklock.daemon
sudo pfctl -a com.apple/050.LeakLock -F rules
```

Удаление: «Настройки» → «Удалить службу…», затем удалите приложение. Журнал службы
лежит в `/var/log/leaklock.log`.
