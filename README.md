# LeakLock

Приложение для строки меню macOS, которое работает как второй, ручной kill switch:
если VPN не подключён, интернет на Mac заблокирован. Это защищает от утечки реального
IP, когда встроенный kill switch VPN-клиента (например, AmneziaVPN) не сработал.

Блокировку делает встроенный файрвол macOS (`pf`), поэтому ни платный аккаунт Apple
Developer, ни Network Extension не нужны.

## Что блокировать: два режима

- **Только адреса из VPN** (по умолчанию). Служба смотрит, какие маршруты VPN-клиент
  направляет в туннель (например, `0/1` и `128.0/1` у AmneziaVPN, за вычетом адресов,
  которые раздельное туннелирование пускает напрямую), и запоминает их. Без VPN
  блокируются только эти адреса, остальной трафик идёт как обычно. IPv6 вне туннеля
  блокируется всегда, чтобы сайты не обходили VPN через IPv6. Пока маршруты ни разу
  не были получены (VPN ещё не подключался), блокируется всё.
- **Весь интернет.** Без VPN не работает ничего, кроме исключений ниже.

Туннель определяется как интерфейс `utunN` с наибольшим числом IPv4-маршрутов. Свои
`utun0…5` macOS использует только под IPv6, поэтому их служба не выбирает.

### Два типа раздельного туннелирования в Amnezia

В Amnezia есть два противоположных режима раздельного туннелирования, не путайте их:

1. **Адреса из списка ДОЛЖНЫ открываться через VPN.** Через VPN идут только сайты из
   списка. В режиме «Адреса из VPN» LeakLock без VPN блокирует только их. Сервисы
   проверки IP (api.ipify.org, checkip.amazonaws.com, icanhazip.com, ifconfig.me) тоже
   должны быть в списке, иначе проверка не пройдёт и защита останется закрытой.
2. **Адреса из списка НЕ ДОЛЖНЫ открываться через VPN.** Через VPN идёт всё, кроме
   сайтов из списка. В режиме «Адреса из VPN» LeakLock без VPN блокирует всё, кроме них.

В режиме «Весь интернет» тип не важен: без VPN блокируется всё.

### Несколько VPN-клиентов

Включайте клиенты по очереди и добавьте в настройки IP серверов каждого. При каждом
подключении IP проверяется заново, и запоминаются маршруты текущего клиента; пока VPN
выключен, действуют маршруты последнего подключённого. Два клиента одновременно не
поддерживаются: открывается только один туннель.

## Как это работает

Небольшая фоновая служба (`leaklockd`, запускается от root через launchd) держит
собственный якорь pf `com.apple/050.LeakLock` в одном из трёх режимов:

| Режим | Когда | Что разрешено |
|---|---|---|
| Заблокировано | туннеля VPN нет | только исключения (см. ниже) |
| Проверка | туннель есть, внешний IP ещё не проверен или не совпал | исключения, HTTP и DNS через туннель (только для проверки IP) |
| Открыто | внешний IP, видимый через туннель, совпал с IP VPN-сервера | исключения и весь трафик через этот `utunN` |

Исключения действуют всегда: loopback, DHCP, link-local и mDNS (они не выходят за
пределы локального сегмента), прямая связь Apple-устройств через AWDL (AirDrop, AirPlay,
повтор iPhone, Sidecar), IP-адреса
VPN-сервера (иначе VPN-клиент не сможет подключиться), а также, если включено в
настройках, локальная сеть и DNS.

Локальные исключения (loopback, AWDL, link-local, локальная сеть) пропускаются без
отслеживания состояния (`no state`). Иначе ответы Mac на входящие соединения от
соседних устройств (приём AirDrop, повтор iPhone) упирались бы в блокировку: pf
не создаёт состояние для входящих пакетов, а правило с состоянием пропускает только
первый SYN, но не ответный SYN-ACK.

Внешний IP проверяется запросом к сервисам api.ipify.org, checkip.amazonaws.com,
icanhazip.com и ifconfig.me (берётся первый ответивший). Сокет запроса жёстко привязан
к проверяемому `utunN` (`IP_BOUND_IF`), поэтому проверка физически не может уйти через
Wi-Fi и показать сервису реальный IP: если туннеля нет, она просто не состоится.

Защита работает в режиме fail closed:
- если служба упала, правила pf остаются загруженными;
- если файл настроек повреждён, защита остаётся включённой без исключений;
- если не указан ни один IP сервера, интернет заблокирован.

Соединения через туннель привязаны к нему (`keep state (if-bound)`). При любом
ужесточении (старт службы, включение защиты, обрыв туннеля, восстановление правил)
служба сбрасывает таблицу состояний pf, чтобы ни одно уже установленное соединение не
продолжило работать в обход правил.

Раз в секунду служба проверяет, что pf включён, правила на месте, основная цепочка
вызывает `com.apple/*` и ни один сетевой интерфейс не исключён через `set skip`, и
восстанавливает всё это при необходимости.

Таблица адресов VPN для режима «Адреса из VPN» запоминается, только когда туннель
подтверждён и маршруты не менялись 5 секунд, чтобы не сохранить неполную таблицу во
время переподключения.

## Установка

1. Скачайте `LeakLock-x.y.z.dmg` из Releases (или из артефактов сборки в Actions)
   и перетащите **LeakLock** в «Программы».
2. Запустите приложение. Оно не подписано Apple, поэтому macOS его заблокирует.
   Откройте **Системные настройки → Конфиденциальность и безопасность**, внизу
   нажмите **«Всё равно открыть»** и подтвердите. Это нужно сделать один раз.
3. В меню щита в строке меню нажмите **«Установить службу…»** и введите пароль
   администратора.
4. В **Настройках** добавьте IP-адрес(а) своего VPN-сервера, затем включите **«Защиту»**.

## Обновление

LeakLock сам проверяет последний релиз на GitHub при запуске и раз в 6 часов; вручную —
кнопкой «Обновления» в меню или «Проверить обновления» в настройках. Если вышла новая
версия, в меню появляется кнопка «Обновить»: приложение скачивает DMG из релизов этого
репозитория (другие адреса не принимаются), проверяет, что внутри LeakLock нужной версии
с целой подписью, заменяет себя и перезапускается. Сразу после перезапуска оно попросит
пароль администратора, чтобы обновить службу. Старая версия удаляется только после того,
как новая встала на место.

Без VPN защита блокирует и GitHub, поэтому проверка работает, когда VPN подключён.

## Безопасность и ограничения

LeakLock защищает от случайных утечек: VPN упал, переподключается, клиент не включил
свой kill switch. От вредоносной программы, уже запущенной под вашей учётной записью,
он не защищает, и вот почему:

- **Настройки без пароля.** Менять настройки службы может любой процесс пользователя
  из группы «Администраторы» (так устроено меню: переключатели работают без пароля).
  Обычные пользователи Mac могут только смотреть статус.
- **Приложение лежит в папке пользователя.** Программа под вашей учётной записью может
  подменить LeakLock.app и дождаться, пока вы введёте пароль для обновления службы.
  Но такая программа и так может показать поддельное окно пароля.
- **Обновления.** Подлинность обновления держится на HTTPS и на аккаунте GitHub, с
  которого публикуются релизы: DMG скачивается только из релизов этого репозитория.
  Подписи разработчика Apple нет, поэтому проверка подписи подтверждает только
  целостность пакета, а не автора.

В режиме «Адреса из VPN» список того, что блокировать, берётся из таблицы маршрутов.
Её может дополнить чужая сеть (поддельный DHCP, атака TunnelVision), поэтому LeakLock
не доверяет исключениям шире /8 и полностью отказывается от исключений, если они
покрывают больше четверти адресов туннеля. В непроверенной сети (кафе, отель)
надёжнее режим «Весь интернет»: в нём таблица маршрутов не используется.

## Если что-то пошло не так

- **С VPN сайты не открываются.** Скорее всего, DNS указывает на роутер в локальной
  сети. Включите «Разрешить локальную сеть без VPN» или «Разрешить DNS без VPN».
- **VPN не подключается, когда защита включена.** Если в конфигурации VPN сервер
  указан доменом, а не IP, включите «Разрешить DNS без VPN».
- **«Внешний IP не совпадает».** Через туннель виден другой адрес, например у
  сервера отдельный выходной IP. Когда VPN точно подключён, добавьте этот адрес в
  настройках кнопкой «Добавить текущий внешний IP».
- **Нужно срочно снять блокировку без приложения:**
  ```sh
  sudo launchctl bootout system/com.leaklock.daemon
  sudo pfctl -a com.apple/050.LeakLock -F rules
  ```
- Лог службы: `/var/log/leaklock.log`. Текущие правила:
  `sudo pfctl -a com.apple/050.LeakLock -s rules`.

## Удаление

Настройки → «Удалить службу…», затем удалите приложение из «Программ». Настройки
остаются в `/Library/Application Support/LeakLock`.

## Сборка

Нужен macOS 13+ и Xcode 15+ (или Swift 5.9+).

```sh
swift test                      # тесты логики
scripts/build-app.sh 0.1.0      # build/LeakLock.app и build/LeakLock-0.1.0.dmg
```

GitHub Actions собирает DMG на каждый PR и push в `main`. Тег `vX.Y.Z` создаёт релиз
с DMG.

## Структура

- `Sources/LeakLockCore`: настройки, генерация правил pf, разбор вывода
  `route`/`pfctl`, логика решений. Не зависит от AppKit, покрыто тестами.
- `Sources/leaklockd`: фоновая служба: следит за маршрутом, проверяет IP, загружает
  правила pf, принимает команды через Unix-сокет `/var/run/com.leaklock.daemon.sock`
  (менять настройки может только администратор).
- `Sources/LeakLock`: приложение для строки меню на SwiftUI.
- `Resources`: Info.plist, plist для launchd, скрипты установки и удаления службы.
